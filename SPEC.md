# Docsmith

## Problem

Writing and maintaining documentation for GitHub repositories is manual and tends to go stale.

## Goal

Automatically generate documentation for the user's GitHub repos.

## Target users

Developers who own GitHub repos, including the requester and other developers.

## Project type

Web app: Web app where the user connects GitHub, picks a repo, and generates documentation.

## Core features

### F1. Generate documentation for a repo

User selects a connected GitHub repo and the app generates a README, an API reference, and a markdown docs folder.

Acceptance checks:

- User can select a repo and start generation
- Output includes a README, an API reference and markdown docs files
- User can preview the generated docs in the app

### F2. Open pull request with generated docs

After generation, the user can have the app commit the docs to a new branch and open a pull request on the repo.

Acceptance checks:

- User can click a button to open a PR with the generated docs
- A PR appears on GitHub containing the generated files
- The default branch is not modified directly

### F3. Sign in with GitHub

Users authenticate with GitHub and see their repos.

Acceptance checks:

- User can sign in with GitHub
- User sees a list of their repos after signing in
- User can sign out

## Out of scope

- Non-GitHub hosts (GitLab, Bitbucket)
- Automatic regeneration on every push
- Team or organization management

## Data model

### Entities

- **User**: A developer signed in via GitHub.
  Fields: id, githubId, username, createdAt
- **Repository**: A GitHub repo the user has generated docs for.
  Fields: id, userId, githubRepoId, fullName, defaultBranch
- **Generation**: One documentation generation run for a repo.
  Fields: id, repositoryId, status, output, pullRequestUrl, createdAt

### Relationships

- User → Repository (one-to-many): A user has many repositories.
- Repository → Generation (one-to-many): A repository has many generations.

## Integrations

- **GitHub**: Access the user's repositories to read code and generate documentation.
- **LLM provider API**: Reads repository code and generates documentation text.

## Auth

Sign in with GitHub (OAuth); the same grant is used to read repos and open pull requests.

## Deployment target

Vercel for the web app, with a managed Postgres database.

## Constraints and preferences

- Documentation is generated by an LLM that reads the repository code.
- Never modify the default branch directly; changes go through a pull request.
